\section{Monotonicity}
\label{sec:monotonicity}
\subsection{Domain structure and monotonicity relations}
\label{subsec:monotonicity}

For the state $s$ introduced in Equation~\eqref{eq:state}, plausible monotone relationships between individual state components and the $Q$-value can be observed:

\begin{itemize}
  \item $t$ \textbf{(DECREASING)}: The more time has already elapsed, the fewer future requests
        can still be accepted -- the expected remaining reward decreases.
  \item $C_k$ \textbf{(INCREASING)}: More remaining capacity of a resource increases the room for accepting future requests and can only increase the expected remaining rewards.
  \item $r$ \textbf{(INCREASING)}: A request with higher reward should never
        be valued worse than one with lower reward.
  \item $q_k$ \textbf{(DECREASING)}: A higher resource demand of the current request restricts the
        remaining capacity more strongly and can only decrease the future reward, when accepted.
  \end{itemize}

A standard DQN (cf.\ \texttt{standard\_dqn.py}) approximates $Q(s,a)$ with a generic feedforward
network and has no guarantee of respecting those relationships. 

To make use of this domain knowledge, we exploit to enforce the monotonicity relations \textit{structurally} in the network architecture, rather than hoping a generic network learns them. Remark that this is a stronger approach than simply encouraging monotonicity as a soft penalty term in the loss function.

In this chapter we \textit{(first examine to what extent the monotonicity relations are respected by a standard DQN and then)} introduce a special network architecture, that enforces them structurally. This leads us to so called Lattice Networks.


\subsection{Lattice Layers}
\label{subsec:lattice}

As mentioned above, the central idea is to use the structural information of the \ac{drausp} problem directly instead of expecting a generic function approximator to discover it from data alone. A natural way to encode this structure is the lattice architecture: 
\vspace{0.5cm}

\textbf{Calibration.} 
Each input feature is first passed through a \textit{monotone calibration function}, which maps it into a normalized range $[0,1]$ while preserving its direction of monotonicity. 
Remark that by this calibration step, features with decreasing monotonicity (e.g., $t$ and $q_k$) are flipped, so that all subsequent layers only need to ensure monotonicity in increasing direction.

\textbf{Lattice.}
The resulting values of the calibrated features are combined by a multi-dimensional interpolation rule over a learned grid. 
In other words, the network does not just learn arbitrary nonlinear dependencies, it learns a monotone function over the input space. 

A single lattice with $d$ inputs has $2^d$ learnable corner weights (assuming a grid size of 2 per axis) and is evaluated via $d$-linear interpolation. Figure~\ref{fig:lattice-cube} illustrates this for $d=3$. 


\textbf{Computing the function value.} The output value $\hat{Q}$ of a lattice for the calibrated inputs
$(x_1,x_2,x_3) \in [0,1]^3$ is computed as a (trillinear) convex combination of the $2^3=8$ corner weights $\theta_{ijk}$, $i,j,k \in \{0,1\}$, of the cube:
\begin{equation*}
  \label{eq:trilinear}
  \hat{Q}(x_1, x_2, x_3) = \sum_{i,j,k \in \{0,1\}} 
    \Big[ i x_1 + (1-i)(1-x_1) \Big] 
    \Big[ j x_2 + (1-j)(1-x_2) \Big] 
    \Big[ k x_3 + (1-k)(1-x_3) \Big] \; \theta_{ijk}.
\end{equation*}
To illustrate, consider the two-dimensional case  with the four corner weights $\theta_{00}, \theta_{10}, \theta_{01}, \theta_{11}$:
\begin{equation*}
  \hat{Q}(x_1, x_2) = (1-x_1)(1-x_2)\,\theta_{00} + x_1(1-x_2)\,\theta_{10} + (1-x_1)x_2\,\theta_{01} + x_1 x_2\,\theta_{11}.
\end{equation*}
\vspace{0.5cm}

Take care of the calibration step which is essential: each raw quantity ($t$, $C_k$, $r$, $q_k$) is transformed by a monotone 	\textit{NumericalCalibrator} into $[0,1]$, so that increasing and decreasing variables can be handled by the same interpolation machinery. 

However, as $d$ grows, the number of corner weights grows exponentially ($2^d$), which makes a single lattice over all $2+2K$ state components intractable for \ac{drausp} instances with several resources $K$ (cf.\ \texttt{full\_lattice.py}).

To retain the benefits of the lattice principle while scaling to larger state spaces, we use the \emph{Deep Lattice} idea (\texttt{deep\_lattice.py}) inspired by \textcite{you2017}.

\subsection{Deep Lattice architecture for DRAUSP}
Instead of one very large lattice, we compose many small 3-input lattices in a layered architecture. This preserves the same structural monotonicity guarantees as a single lattice, but distributes the complexity across several local modules that can be trained jointly. 
\subsubsection{Model architecture}

In our concrete network, this decomposition is implemented as follows:

\textbf{Layer 0 -- calibrators.} Each raw feature ($t$, $C_k$, $r$, $q_k$) passes through its own
\texttt{NumericalCalibrator}: a piecewise-linear, monotonic function that maps the value to
$[0,1]$ while encoding, once and for all, the monotonicity direction (INCREASING/DECREASING)
established in Section~\ref{subsec:monotonicity}. Remember again, all subsequent layers only
need to be \emph{increasing} from now on.

\textbf{Layer 1 -- intra-resource lattice ensemble.} For each resource $k$, the calibrated
features are combined into three domain-motivated groups of three:
\begin{itemize}
  \item $A_k = [t, r, C_k]$ (time/reward/capacity),
  \item $B_k = [C_k, q_k, r]$ (capacity/demand/reward), and
  \item $C_k = [t, C_k, q_k]$ (time/capacity/demand).
\end{itemize}
Each group is processed by \texttt{lattice\_units} many independent $2\times2\times2$ lattices
(an ensemble), so that Layer~1 can learn several alternative nonlinear, but guaranteed monotonic,
combinations of these quantities. 
For each lattice, the $2^3=8$ corner weights of each lattice are learned independently, and the output is a single scalar per lattice unit.
We average the outputs of the \texttt{lattice\_units} many ensemble lattices of each group by taking the arithmetic meanto produce a single scalar. This is justified because an arithmetic mean of monotonic functions is itself monotonic, so the resulting output of each group is still guaranteed to be monotonic in its inputs.

So we end up with $3K$ scalars, one per group and resource, after Layer~1. 

\textbf{Intermediate calibrators.} Every one of the resulting $3K$ (group, resource) values from
Layer $1$ receives its own \texttt{NumericalCalibrator} (monotonically \emph{increasing}) that
renormalizes it back to $[0,1]$. This is necessary so that it can again be used as a valid grid
coordinate in Layer $2$.

\textbf{Layer 2 -- cross-resource lattices.} While Layer~1 can only model interactions
\emph{within} one resource $k$, Layer~2 combines one calibrated output each from the
groups $A$, $B$, and $C$ of different resources $k$ into new 3-input lattices. This allows the
network to learn, for example, how the capacity situation of resource~1 interacts with the
time-pressure/reward profile of resource~2 -- an interaction that Layer~1 cannot capture by
construction. A rotating resource offset generates exactly $K$ such triplets, so that the number of
lattices in Layer~2 grows linearly with the number of resources $K$. Concretely, for each offset
$i=0,\dots,K-1$ one triplet is formed from resource $k_A=i$ in group $A$, $k_B=(i+1)\bmod K$ in
group $B$, and $k_C=(i+2)\bmod K$ in group $C$, so sweeping $i$ over all $K$ resources yields
exactly $K$ triplets instead of enumerating all $K^3$ possible $(k_A,k_B,k_C)$ combinations.
\textbf{Output layer.} A \texttt{Linear} outputlayer aggregates all Layer-2 outputs into one $Q$-value
per action. Its weights are clamped to $\geq 0$ after every optimization step
(\texttt{apply\_constraints()}), so that a positive (monotonic) effect from the preceding layers
cannot be reversed by negative weights in this final step. This makes $Q(s,a)$ monotonic in $t$, $C_k$, $r$, and $q_k$ - enforced by the architecture.

\subsubsection{Model parameters}

To get an idea of the model complexity we now investigate the number of learnable parameters in the Deep Lattice architecture. The following analysis is valid for any number of resources $K$, any number of calibrator keypoints $P$, any ensemble width $U_1$ in Layer~1, any ensemble width $U_2$ in Layer~2, and any number of actions $D$.

\begin{itemize}
  \item \textbf{Layer 0 (input calibrators).} There are $2+2K$ raw features
        ($t$, $C_1,\dots,C_K$, $r$, $q_1,\dots,q_K$), each passed through its own calibrator
        with $P$ keypoints, contributing
        \[
          (2+2K)\,P
        \]
        parameters.

  \item \textbf{Layer 1 (intra-resource lattice ensembles).} For each of the $K$ resources, the
        three groups $A_k, B_k, C_k$ are each processed by $U$ independent
        $2\times2\times2$ lattices (the ensemble). With $8$ corner weights per lattice this
        contributes
        \[
          3\,K\,U \cdot 8 \;=\; 24\,K\,U
        \]
        parameters. The subsequent averaging over the $U$ ensemble members is a fixed
        arithmetic mean and introduces no additional parameters.

  \item \textbf{Intermediate calibrators.} Each of the $3K$ scalars produced by
        Layer~1 receives its own calibrator with $P$ keypoints, contributing
        \[
          3\,K\,P
        \]
        parameters.

  \item \textbf{Layer 2 (cross-resource lattices).} For each of the $K$ lattices in Layer 2, the
        corresponding triplet is evaluated by $U_2$ ensemble members of a $2\times2\times2$ lattice, contributing
        \[
          K\,U_2 \cdot 8 \;=\; 8\,K\,U_2
        \]
        parameters.

  \item \textbf{Output layer.} A \texttt{Linear} layer maps the $K\,U_2$ outputs of Layer~2 to
        $D$ $Q$-values (one per action), contributing weight matrix and bias:
        \[
          (K\,U_2 + 1)\,D
        \]
        parameters.
\end{itemize}

Summing all five contributions gives a count of

\begin{equation}
  \label{eq:deep-lattice-params}
  N_{\text{DeepLattice}}(K,P,U,U_2,D) \;=\; (5K+2)\,P \;+\; 24\,K\,U \;+\; 8\,K\,U_2 \;+\; (K\,U_2+1)\,D.
\end{equation}
many parameters in total.

For the DRAUSP instance used in our experiments ($K=4$ resources, $P=8$ calibrator keypoints,
ensemble widths $U_1=4$ and $U_2=2$, and $D=4$ actions), Equation~\eqref{eq:deep-lattice-params}
evaluates to
\[
  N = (5\cdot4+2)\cdot8 \;+\; 24\cdot4\cdot4 \;+\; 8\cdot4\cdot2 \;+\; (4\cdot2+1)\cdot4 = 660
\]
learnable parameters.
