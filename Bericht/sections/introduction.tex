\subsection{Motivation and Problem Statement}
\label{subsec:motivation}

Many real-world planning problems require an \textit{online} decision maker to accept or reject incoming requests in real time, without knowledge of which requests will arrive in the future. Decision makers are faced with the trade-off: accepting a low-value request now may consume capacity that a more valuable
request would have needed later, while rejecting too eagerly leaves capacity unused. Classical
revenue management addresses this trade-off for single, homogeneous resources, but many practical
settings additionally require a request to be placed as a single, contiguous, unsplittable block
across \emph{several} resources with different capacities at once, which substantially complicates the
decision problem.

The problem of interest in this paper is the \emph{Dynamic Request Acceptance and Unsplittable Scheduling
Problem} (\acs{drausp}), where the task is to decide whether to accept or reject incoming requests with specific ressource requirements and revenue and how to schedule them across multiple ressources in order to  maximize the cumulated reward. The main difficulty in this problem is that it requires making irrevocable decisions, before knowing which requests will arrive in the future. 

In an upfront decision horizon there arrive $T_d \in \mathbb{N}_{>0}$ many requests succesively. Each request is characterized by a tuple $(r,q)$, where $r$ is the immediate positive reward offered for accepting the request and $q = (q_1, q_2, \ldots, q_{len(q)})$ represents the demanded ressource capacities. 

There are $K \in \mathbb{N}_{>0}$ many resources with different capacities $c_k \in \mathbb{N}_{>0}$ for $k = 1, \ldots, K$. 

Each request must be scheduled in a contiguous block of slots across the available resources without exceeding the capacity $C_k$ of any resource $k$. Once a request is accepted and scheduled, it occupies those slots for the remainder and cannot be splitted, relocated, or revoked. 
Depending on the available capacity and the resource requirements of the request, the decision maker has to decide first whether to accept or reject the request and second, if accepted, how to schedule it across the available resources. In the scheduling of a request of length $len(q)$, the decision maker has to choose a starting position $s \in \{1, \ldots, K - len(q) + 1\}$.
The objective is to choose an acceptance-and-scheduling policy to maximize the total revenue over the decision horizon.


\acs{drausp} is difficult precisely because it is sequential and combinatorial at the same time:
the number of feasible placements for a request grows with the number of resources $K$, and the
value of accepting a request today can only be judged against the (unknown) value of the requests
still to come. \textcite{drausp_lion18} show that exact stochastic dynamic programming solves
\acs{drausp} optimally, but that this approach becomes computationally intractable as the state
space grows with $K$ and the number of requests.
This motivates a reinforcement-learning-based, function-
approximation approach pursued in this report. 

In addition, the problem exhibits domain structure
that a generic learned model does not respect automatically -- e.g., more remaining capacity should
never make a state look worse.
In this paper we exploit whether make usage of meaningful structure explicitly by enforcing a model to incorporate this structure rather than hoping a model learns it, improves the reliability and sample results of the learned policy. Doing so, we will use some Lattice Networks for function approximation.



\subsection{Related Work}
\label{subsec:related-work}

This report builds mainly on two lines of work. The first is formulating the \acs{drausp} as an Markov Decision Process
(\acs{mdp}) and solving it with reinforcement learning, specifically Q-learning. The second is
incorporating monotonicity constraints into the Q-learning model, so that structural knowledge
about the problem can be exploited to improve the learning process.

\textbf{Formulating DRAUSP as an MDP.} The \acs{drausp} was first introduced by
\textcite{drausp_lion18}, who already formulate it as a finite-horizon \acs{mdp} and solve it via
exact stochastic dynamic programming, complemented by a dimension compression algorithm that
yields upper and lower bounds when the state space becomes too large to enumerate exactly. Their
results also show that simple heuristics (e.g., first-come-first-served) are insufficient once
the trade-off between immediate and future revenue becomes non-trivial, motivating more
sophisticated, learning-based acceptance and scheduling policies. The authors set up instances for
numerical experiments with up to $K=10$ capacity slots. We will use the same numerical instances
to evaluate the performance of the monotonicity-constrained \acs{rl} models introduced in this report, later on.

\textbf{Value-based deep reinforcement learning.} Exact dynamic programming, as used by
\textcite{drausp_lion18}, suffers from growing instances and becomes computationally intractable for 
larger instances. \Acs{rl} addresses this by learning an action-value
function $Q(s,a)$ from sampled experience instead of solving the stochastic dynamic programming problem
exactly. \textcite{watkins1992} introduce Q-learning, the algorithm underlying all value-based
\acs{rl} methods used in this report, and \textcite{suttonbarto2018} provide the standard reference
for the underlying \acs{mdp} formalism and solution methods. \textcite{mnih2015} extend Q-learning
with a deep neural network as function approximator (\acs{dqn}), together with experience replay
and a target network to stabilize training. This is exactly the architecture that forms the baseline 
for our models later on.

\textbf{Monotonicity constraints in learned models.} A plain \acs{dqn} has no built-in guarantee
that $Q(s,a)$ respects domain knowledge such as ``more capacity is never worse'' -- such
relationships can, at best, be encouraged through additional loss terms, without any guarantee
that they hold at inference time. \textcite{you2017} instead propose enforcing monotonicity
\emph{structurally}, in the architecture itself: \emph{Deep Lattice Networks} alternate layers of
monotonic calibrators and ensembles of interpolated look-up tables (lattices), each of which is
constrained during training so that the composed, end-to-end function is provably monotonic in a
user-specified subset of its inputs. This report adopts that architecture for the \acs{drausp} $Q$-function,
using it to enforce the monotonicity relations postulated in
Section~\ref{subsec:monotonicity} by construction rather than by regularization.

In summary, this report combines the \acs{mdp} formulation of the \acs{drausp} introduced by
\textcite{drausp_lion18} with value-based deep \acs{rl} \parencite{watkins1992,mnih2015} to scale
beyond exact dynamic programming, and further constrains the learned $Q$-function to be
structurally monotonic using the Deep Lattice Network architecture of \textcite{you2017}.
